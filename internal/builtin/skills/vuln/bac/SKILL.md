# 访问控制失效（BAC）

## 漏洞本质

用户能否访问/操作不属于自己的资源。三种形态：

- **未授权访问 Unauthorized**：anonymous（无凭证）能拿到需要认证的资源
- **垂直越权 Vertical**：低权限角色能拿到高权限专属的资源
- **水平越权 Horizontal**：同级用户能拿到别人的私有资源

## 两种执行模态（贯穿全篇；文末块引用即模态选择原则）

判定逻辑两模态共用，但"一个身份物理上是什么、怎么换身份、读什么信号"完全不同：

| | 请求重放模态（http_request + 流量字典） | 浏览器渲染模态（drive_browser） |
|---|---|---|
| **身份 =** | `http_request` 的 `identity` 参数选中的凭证集 | 同一容器内一个独立浏览器（独立 jar，已登录为该账号） |
| **换身份** | 同一请求改 `identity` 值重发 | 各 identity（=账号名，如 admin/lowpriv）各开一个浏览器、各自登录、各自 `open` 同一功能 |
| **anonymous** | `"identity": ""`——不注入任何凭证、不带会话 Cookie、响应不落会话 | 从没登录过的 identity（空 jar）`open` |
| **枚举对象** | 改请求里的对象引用值重发 | 在某身份浏览器 `open` 不同对象的 URL |
| **判定信号** | 响应 `status + body` | **渲染后 DOM**（`state` 的带编号元素清单 / `get html`）——业务面板/他人数据有没有真渲染出来 |

> **选哪种模态——无预设默认，按目标形态与硬条件选**：漏洞执行在 JS 里 / 数据无干净后端 JSON 边界 / WAF 只认浏览器（真实目标常态）才**必须**浏览器；否则传统服务端 / 干净 REST 走请求重放，SPA / 重前端 / 有风控浏览器常为主路径。前端"按角色藏按钮"不算，那要打它背后的后端接口。本节只澄清两模态各自怎么做。

**关键**：浏览器模态不靠"换凭证值"，而是**各身份各自的浏览器登录态 + 各自渲染结果并排对比**（admin 浏览器渲染出管理面板 vs 低权浏览器被踢回登录 / 403）。截图会自动落 `$OUTPUT_DIR`（操作员可见、可作 finding 证据），但你（LLM）读到的信号是**渲染后 DOM 文本**。下文 anonymous / 枚举 / 证据都按两模态各一套；**判定逻辑（anon 触顶 → 身份数 → 原则 1-5 → 误报）两模态一致，只是"信号"从响应文本换成渲染后 DOM**。

## 身份原语：http_request 的 identity 三态（请求重放模态的根基）

`http_request` 与凭证库（credential store）双向集成，`identity` 一个字段完成身份切换：

- **省略 / null**：注入该 host **全部可用凭证**（持久身份 + 本任务会话 Cookie）。日常探测用；多身份对比**不要用**（多身份凭证同键时按身份名序只取先到，结果不是"某一个身份"）
- **`"身份名"`**（如 `"admin"`）：只注入该身份的凭证；响应 Set-Cookie 自动**归属该身份**续期（不污染任务会话）
- **`""`（空串）**：**匿名**——不注入任何凭证、不带任务会话 Cookie、响应不落任何会话状态。BAC 的 anonymous 测试就用它，**不要**手抄凭证再删掉——原生匿名保证一个凭证位都不漏

注入位置全覆盖（headers / query / form body），显式传入的键优先。**响应不自动跳转**（30x 原样返回——认证绕过判定依赖原始状态码）。

## 挖掘方向（思路，不是步骤）

**唯一铁律**：开测前先跑一次 anonymous（请求重放 `"identity": ""` / 浏览器空 jar `open`，见两种执行模态），看响应/渲染。判定原则 1 决定了 anonymous 能访问 → 必判 Unauthorized（触顶所有越权分类），**跳过 anonymous 直接下 vertical/horizontal 结论就是漏判**——这是 BAC 测试最常见的假阴性源。除此之外，怎么挖、用几个身份、按什么顺序——你自己根据目标请求判断。

BAC 的**主轴**是 **多身份对比**——同一功能换不同身份看差异；另有**补充发现手段「枚举对象引用」**（见下）。下面是倾向性的判断，不是规则：

- 目标请求本身不需要任何凭证 → 多半是公开接口，BAC 通常不适用
- 写操作（create / update / delete）的 BAC 危险度通常 > 读操作。**破坏性端点别拿他人真实对象当 anon/枚举的靶子**——网关层（401/403）就能判出"被拒"，不必让 2xx 破坏副作用真正落地才下结论；非看落地不可时，打你自己创建 / 可控的影子对象，别真删真改别人的数据。这不放宽 anonymous 铁律（仍要跑 anon 看网关是否拦），只约束"怎么跑才不造成不可逆破坏"
- 路径或 body 里出现资源标识符（任何 ID、文件名、用户名）→ 多半要测水平越权
- 路径或角色语义指向特权域（管理后台、系统设置、批量操作）→ 多半要测垂直越权

### 枚举对象引用（发现手段，不下结论）

身份对比是"固定对象、换身份"；**枚举是"固定身份、换对象引用"**——把请求里指向某个对象的值改掉，看能不能够到别人的对象。两个动作互补：枚举负责**翻出"别人的对象"**，对比/自证负责**定罪**。

- **先认出"对象引用"在哪（别预设就是 `id`）**：跨 **path 段 / query / body / header（含非 session cookie）** 综合判断——① 看**值的形状**（连续数字、UUID、Base64/hash、文件名、order_no、用作键的用户名/邮箱）；② 看**名的语义**（`*_id` / `user` / `account` / `file` / `order` / `ref` / `no`…）；③ **改一下看响应是否换成了"另一个对象"**（换了才是引用）。名与值要合判。**排除**控制类（`page` / `limit` / `sort` / `format`）、CSRF、以及 session/auth token 本身（那是"换身份"的活）。
- **怎么变值枚举**：顺序 ID（1→2→3）、UUID±1、Base64/hash 解开再±、文件名/order_no 邻近值。请求重放模态改请求值重发；浏览器模态在某身份浏览器 `open` 换了对象的 URL。**小步枚举**——先试几个相邻值确认可枚举，别一上来狂跑（撞限速反而测不下去，见误报排除）。
- **底线：枚举本身永远不下结论。** 改 `id=1→2` 拿到 200 + 不同数据**默认是你自己的另一条记录或公开数据**（见误报排除）。枚举出的候选必须丢回判定原则定罪：**有 ≥2 身份走对比式、只有 1 身份走自证式 IDOR**（详见下文身份数约束与判定原则 3）。

### 身份从哪来——与下发来源无关（关键）

"身份" = 一个你能认证进去的权限上下文，**不等于 `read_credentials` 的行**。来源有三类，能凑出几个算几个：

1. **`read_credentials` 已录入的凭证**（代理捕获常态：任务启动前已录入）
2. **brief 直接给的登录凭据对**（人工下发常态：planner 把"某高权账号、某低权账号"两组账密透传到 brief）→ 你登录把它**变成**可用会话并**录入成命名身份**
3. **recon / 探测中发现的登录入口**（任何模式：看到登录表单就能注册一个新身份）

**身份数按"可获得数"算，不是按 `read_credentials` 行数算**——人工下发时 `read_credentials` 常返空 `[]`，但 brief 给了一个高权 + 一个低权两组账密 → **可获得身份数 = 2**，足以展开垂直越权。把空 `read_credentials` 误读成"0 身份不能测越权"是人工下发场景下 BAC 最大的假阴性。**反向也一样错**：brief 给的账号若登不进去（密码错 / 账号锁定——登录表单连试 2 次仍落回登录页就停手，别把账号锁死），该身份**不算**"可获得"——别拿登录失败的幻影身份凑对比式矩阵。"可获得"以**你真正拿到了会话**为准。

**怎么把登录凭据变成可对比的命名身份**（多身份矩阵的前提——每个身份要有独立、可复用的凭证集）：

- **请求重放模态**：先 `list_traffic` / `view_traffic` 查该 host 是否已有现成登录流量（浏览器登过、或代理捕获抓到的流量里可能直接带会话 Cookie，`view_traffic` 连 httpOnly cookie 头都看得到，抄 URL/method/headers/body 即可重建）。没有就自己登录：`http_request` `GET` 登录页抽 CSRF token（表单一次性隐藏字段，名字各框架不同，如 `csrf_token` / `authenticity_token` / `_token` / `__RequestVerificationToken`）→ `POST` 账密 + token → 从响应头抄 `Set-Cookie` → `write_credential` 把它**与 Authorization 等 token 一起**录入为命名身份（`{"type":"headers","key":"Cookie","value":"..."}`）。之后矩阵每行 `http_request` 传对应 `identity` 即可，凭证注入/续期全由工具管。
- **浏览器渲染模态**：每个账号一个 `identity`（=账号名）开独立浏览器，登录页 `state` → `input` 账密 → `click` 提交。登录过程的真实认证请求会被浏览器服务 CDP 抓进流量字典（`tool=browser`、`identity=账号名`，`list_traffic` 可查）——**取舍：每身份首个导航 GET 会漏抓，登录 POST / 后续 XHR 不漏**，BAC 要的带凭证请求都在。
- **模态互通**：浏览器登录后想走请求重放？`view_traffic` 读该身份被 CDP 抓下的真实请求（含 httpOnly Cookie 头）→ `write_credential` 录成命名身份 → `http_request identity` 直接用。浏览器不读 redis 凭证（反向注入不存在）。

身份数（含可获得的）决定能测哪几类，硬约束——但要分**对比式**与**自证式**两条定罪路径：

- **可获得非匿名身份数 = 0**：只能测 Unauthorized（anonymous vs 目标自带身份）
- **可获得非匿名身份数 = 1**：**对比式** vertical / horizontal 凑不出（vertical 需 ≥1 高 + ≥1 低，horizontal 需 ≥2 同级，单身份都不够）；但有两条单身份仍可定罪的路：① **自证式 IDOR**——枚举对象引用，响应**自报归属他人**即成立（判定原则 3）；② **功能级垂直越权**——该（低权）身份直接调一个**本质特权的功能**（删他人账号 / 改系统配置 / 批量操作等只该管理员做的事）且**操作真生效**，凭"功能本质特权 + 生效"即可判 vertical，不必高权身份对照。这条比对照式略主观——**功能是否真特权拿不准，就收敛到不报**。除此之外仍只能下 Unauthorized
- **可获得非匿名身份数 ≥ 2**：对比式 vertical / horizontal 全部展开（仍可叠加枚举找候选对象）

## 重要前提：anonymous 是 LLM 临时构造的测试概念

`read_credentials` 返回的列表里**不含 anonymous**——anonymous 不是预录入的"半成品身份"，而是你按需构造的测试请求形态（请求重放 = `identity:""`，浏览器 = 空 jar 的未登录 identity）。

### anonymous 必须真发一次请求看响应

禁止凭"受保护页应该会跳 login"脑补一行塞进矩阵（脑补的 anonymous 行 = 假 evidence，污染整个判定，违反 finding 证据红线）。

- **请求重放**：`http_request` 传 `"identity": ""`。工具保证不注入任何凭证、不带会话 Cookie（这是匿名原语的契约，别再手抄凭证模板删删改改——手工替换漏一个位置就是假阳性）。
- **浏览器**：用一个**从没登录过的 identity**（如 `identity:"anon"`）`open` 受保护 URL——空 cookie jar = 服务端按未认证处理，返回什么（302→login / 401 / 登录页本身）就是**真**的 anonymous 结果。**必须真 `open` 看渲染，别脑补。**

### 判定时的注意

**判定 anonymous 是否成功只看响应**（status + body），不看请求形态——`identity:""` 是参数选择、空 jar 是身份状态，出现在请求侧不代表认证成功。**浏览器路径同理**：只看渲染结果（登录页 / 302 = 被拒，业务面板 = 能进），不看 identity 叫什么名。

## 判定原则（关键 5 条，按优先级）

> **从「可获得身份数」往后——身份数定罪 + 以下 5 条 + 误报排除，是两种执行模态共用的同一套决策树**：逻辑分支完全一样，模态只决定每个节点"读什么信号"——请求重放看「响应 status + body」、浏览器渲染看「渲染后 DOM（state / get html）」。只有"怎么跑出这一步 / 怎么换身份 / 留什么证据"（anonymous 执行、枚举动作、evidence 形态）按两模态各一套，判定逻辑本身不分叉。

### 1. anonymous 能访问 → 必判 Unauthorized（最高优先级）

哪怕同时还有低权限用户也能访问、哪怕 URI 含 `/admin`——只要 anonymous 拿得到业务数据，就只能是 Unauthorized Access。理由：anonymous 能进意味着认证机制本身失效，更具体的越权分类失去意义。

### 2. "成功访问"必须双重判断（缺一不可）

仅靠状态码会大量误报。同时满足（**请求重放模态**看响应；**浏览器模态**按括注看渲染）：

- **HTTP 状态**：2xx（含 200 / 201 / 204 / 206），明确排除 4xx / 5xx（浏览器模态：页面没被重定向到登录页、没弹 403/无权限）
- **响应内容**：包含业务数据，不是 `{"error": "..."}` / `{"detail": "Unauthorized"}` / 空响应——状态码 200 + 错误体仍是被拒绝（浏览器模态：渲染后 DOM 里真的画出了目标业务面板/数据，不是登录表单或"无权限"提示）

### 3. 资源权限本质判断（不要靠路径模式匹配，看响应数据语义）

不要因为 URI 含 `/admin` 就认定高权限资源、含 `/user` 就认定用户私有。要看**响应内容的本质属性**：

- 系统配置 / 全局设置 / 所有用户列表 / 审计日志 → 高权限资源（用于判 vertical）
- 个人资料 / 订单 / 私有文件 / 个人设置 → 用户私有资源（用于判 horizontal）

**看数据语义，不仅看体积**：两个身份返回 body 大小相同不代表是同样数据。不同 user_id 但字段结构相同 → 各看自己的数据（无漏洞）；不同身份拿到**相同** ID 的同一份私有数据 → 越权（他们不可能都是所有者）。

**单身份自证式 IDOR（只有 1 个身份时的唯一定罪法）**：没有第二身份做对比时，只有一种情况成立——枚举到的对象**自报了归属他人的身份字段**（请求重放看响应 body、浏览器看渲染后 DOM：出现不是你账号的姓名 / 邮箱 / 手机 / 订单归属 / 收件人等）。判据是"**自证这条数据属于另一个主体**"，不是"数据和我的不一样"——仅"返回不同数据"绝不成立。这条比对比式脆——**拿不准归属就收敛到不报**。

**vertical 还是 horizontal，看「行为身份」与「够到的资源/功能所属权限层级」的关系，不是 URL 字样**：低权身份够到高权身份专属的资源或功能（改别人的高权数据、执行只有高权能做的操作）→ vertical；同级身份够到另一个同级用户的私有资源 → horizontal。路径或页面里的 "admin" 之类字样是应用自带的提示、真实目标里通常没有——别据此定方向，据实测出的各身份权限差异定。

### 4. 重定向需要看 Location 综合判断

3xx 不能一刀切（`http_request` 不自动跳转，30x 原样返回，正好逐个看）：

- 302 → 登录页或登录态相关 URL → 访问控制在起作用，**不算**成功访问
- 302 → 业务页面 → 看 Location 和最终响应内容综合判断
- 301 永久移动 → 通常不算成功访问原始资源

### 5. 反直觉：多身份都能访问 ≠ Horizontal

像 `/api/admin/user/delete` 这类接口，如果 anonymous + admin + 普通用户全都能成功执行——这是 Unauthorized（认证失效，anon 能进触顶原则 1），**不是** Horizontal、也**不是** Vertical。

## 误报排除

提交 finding 前先过一遍：

- 静态资源 / 健康检查 / 公共信息（商品列表、文章列表、登录页本身）
- 3xx 重定向到登录页
- 响应虽 200 但 body 是错误消息或空内容
- 单纯"返回不同数据"——是用户看到自己的数据或公开数据，不是越权（**枚举改 id 拿到不同数据本身不成立**，除非响应自报归属他人，见判定原则 3）
- **限速/风控噪声 ≠ 访问被拒**：枚举或多身份重发时突然大面积 `429` / `503` / 连接被重置 / 全部跳验证码，是被速率限制或 WAF 拦的**环境噪声**，不是"访问控制生效"、更不是"没漏洞"。放慢节奏重试；仍不行就如实上报"受限未测透"，别把限速误判成结论
- **操作成功 ≠ 利用成功**：state-changing 请求返 2xx 只证明"调用被接受"，不证明你声称的下游影响成立。若 finding 的影响依赖"使用"你拿到的东西（新建的账号、提升的角色、签发的 token、改/删他人的资源），就**真去用一次**证明它可用——**写越权尤其要换一个身份或原属主读回**，确认目标对象真被改/删，别只凭写请求返 2xx；再下"提权 / 接管 / 篡改生效"结论；没验证就把结论收敛到**确实证明了的那部分**（如"未授权写入成功"），别夸大成 escalation。**警惕响应回显了你没提交的值**（你传 A、响应却是 B / 固定值）——这是输入被忽略或归一化的信号，说明操作未必如响应表面那样生效，下结论前重验

## finding 证据红线

evidence 必须包含：

- **对比式（≥2 身份）证据 — multi-identity 矩阵**：每个测试身份对同一目标的结果对比，不要只贴违规身份那一条。**请求重放模态**：矩阵每行注明所用 `identity` 与响应摘要（凭证注入明细由工具回显的 `applied_credentials` 佐证）。**浏览器渲染模态**：列**每个 identity（=各自账号）各自 `open` 同一受保护 URL 的渲染结果对比**（渲染后 DOM 关键片段 + 自动截图工件），矩阵的"身份"列就是 identity 名
- **自证式 IDOR（单身份）证据**：此路**不要求多身份矩阵**（本就只有 1 个身份）——改为给：① 枚举动作（对象引用被改成了什么值 / `open` 了哪个对象 URL）；② **归属他人的身份字段**（请求重放给响应 body 原文、浏览器给渲染后 DOM 片段，高亮 user_id / 姓名 / 邮箱 / 手机 / 订单归属，证明数据属于另一个主体而非请求者）；③ 请求者自身身份（证明你不是该数据所有者）。缺"自报他人归属"这一条即不成立
- **泄露的敏感字段名**（user_id / email / phone / token 等业务字段）
- **repro_cmd**：违规身份的最小化复现——请求重放模态给最小化 curl 命令（别人 copy 就跑出同结果；凭证位置留占位符）；浏览器渲染模态给「以 identity X `open` 该受保护 URL」的最小化步骤
- 涉及 anonymous 时，矩阵里的 anonymous 行**必须来自真实请求**（`identity:""` 的响应、或空 jar 浏览器 `open` 的渲染）——**禁止凭"应该会 302"脑补**，脑补行是假 evidence；违规身份字面值就是 `anonymous`，不要写空串或 null

**CWE 按形态统一**（finding 去重键含 cwe_id——host+cwe_id+归一化路径+method+parameter，同一形态填飘会直接破坏去重）：未授权访问 = `CWE-862`、IDOR / 对象引用越权 = `CWE-639`、垂直 / 水平越权 = `CWE-863`。同一形态每次填同一个，别在三者间飘。

summary ≤500 字单行，详情进 evidence jsonb。
